# Remote Device Control — 実装仕様（初期設計）

## 目的

iPadのPWAから、所有者が初回登録したAndroid端末を複数管理し、端末を選んで接続する。Android側は明示的な許可と動作表示を維持し、カメラ・マイクのライブ配信を行う。

## 採用方針

- フロントエンド：HTML / CSS / JavaScript
- 配布・ソース管理：GitHub Pages / GitHub
- Android APK：GitHub Actionsでビルド
- Androidネイティブ連携：Kotlinは使用しない。必要な部分はJavaで実装する
- 管理・シグナリング補助：Google Apps Script（GAS）
- 映像・音声：WebRTC（GASをメディア中継に使わない）

## 初回登録と通常接続

1. iPadの管理画面で端末登録を作成し、短時間だけ有効なペアリングQRを表示する。
2. AndroidアプリでQRを読み取り、端末所有者が登録を承認する。
3. Android側でカメラ・マイク権限、通知、バックグラウンド動作を設定する。
4. 以後はiPadの端末一覧から登録済み端末を選択して接続する。
5. Android側には接続・録画/録音状態を常時分かる形で表示し、いつでも停止できる操作を置く。

## 画面ロック中の動作について

Android 13では、アプリが画面表示中にユーザー操作でカメラ・マイクのForeground Serviceを開始し、そのサービスが継続している間は、端末やOSの制約の範囲で画面消灯後もライブ配信を維持できる可能性がある。

ただし、画面ロック中に停止状態からカメラ・マイクを新規起動すること、強制停止後に遠隔から復活させること、電源OFF端末を起動することは通常のアプリでは保証できない。Device Owner登録をしてもカメラ・マイクのプライバシー制限を解除するものではない。

実装では次を区別する。

- **配信中に画面ロック**：継続を試み、端末ごとに実機検証する。
- **未配信・画面ロック中にiPadから開始要求**：OSが許可しない場合は開始せず、Android側でユーザー操作が必要と表示する。
- **アプリ強制停止・端末再起動後**：自動再開を保証しない。再起動後はユーザーがアプリを開いて再開する設計を基本とする。

## GASの役割

GASは端末登録、ペアリング情報の発行・失効、端末の最終オンライン時刻、接続要求などの小さな制御情報を扱う。映像・音声データは保存・中継しない。GASの実行時間・同時実行・Webアプリの通信制約があるため、リアルタイム映像の中継や高頻度の長時間ポーリングには使わない。

WebRTCのシグナリングは offer / answer / ICE candidate の交換が必要。GASを使う実装方式はブラウザからのクロスオリジン通信とApps Scriptの応答仕様を実機検証してから確定する。接続不能なNAT環境に備えたTURNはGitHub PagesやGASだけでは提供できないため、直接接続できないネットワークでは接続できない可能性がある。

## セキュリティ要件

- ペアリングコードは短時間・一回限りで失効させる。
- 端末ごとにランダムな資格情報を発行し、平文でログに残さない。
- 端末削除・資格情報ローテーション・全セッション切断を実装する。
- 接続のたびに対象端末名とカメラ/マイク状態を明示する。
- Android側に撮影・録音中の継続通知と停止ボタンを表示する。
- 第三者端末への無断登録、隠れた録音・撮影、通知を隠す機能は実装しない。
- 本人の明確な同意と権限がある端末だけを管理する。

## 実装フェーズ

1. GitHub Pagesの管理UI、端末一覧、初回ペアリングUI。
2. GASの端末登録・ペアリング・オンライン状態API。
3. Android JavaブリッジとAPKビルドワークフロー。
4. WebRTCのシグナリングと1対1映像・音声。
5. 複数端末切替、通信状態、再接続、ログ。
6. Android 13実機で画面ロック・省電力・再起動時の挙動を検証。
